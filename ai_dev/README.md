# AI 开发助手

开发执行模式可读写工作区、检查差异、运行测试并热重载插件；只读分析模式仅提供查询工具。

## 开发流程

启用「计划 → 开发 → 验证流程」后，复杂任务会被引导先读取必要证据，通过 `update_plan` 维护 pending / in_progress / completed 步骤，再修改、检查 Git diff、测试和报告结果。计划随当前会话事件保存，并在面板事件流显示。简单任务无需创建计划。此流程是模型工作指引，不代表测试必然通过；完成证据仍由现有执行校验器检查。

`batch_read` 支持并发执行 1–8 个独立只读查询，每项返回独立结果或错误；写入、测试、热重载和嵌套批量调用会被拒绝。需要完成证据的验证操作仍应直接调用对应工具。

## 设置

点击面板设置按钮可调整温度、最大工具轮数、历史用户轮数、单工具等待超时、相同参数失败上限、开发与分析附加要求，以及 Skills / MCP / Agent 中央能力。接口和密钥继续由中央 AI LLM 管理。

- 历史按完整用户轮次裁剪，保留最近指定数量，不拆开工具调用与返回。
- 单工具超时限制异步等待；已在底层线程或外部进程执行的操作可能继续运行，超时后应检查实际状态再决定是否重试。
- 同一工具和参数失败达到上限后拒绝再次执行，提示模型改变参数或方案；整个任务仍受工具轮数限制。
- 当前任务的计划记录在会话事件中；每个新用户请求重新建立执行上下文。

## 验证

`python -m unittest discover -s ai_dev/tests -v`

这些回归检查覆盖计划状态、设置边界、批量只读限制和接口设置白名单，不需要运行机器人或模型密钥。实际模型对话与热重载需要在安装后的框架中验证。

## 流程稳定性

- Python 文件新建和编辑都会先做 AST 语法检查；不合法内容不会落盘，返回行号与错误原因供模型修正。
- 文件写入采用同目录临时文件加原子替换，并串行处理本进程的写入，减少中断造成文件不完整的风险。
- `verify_change` 在语法、测试或重载失败时停止后续阶段，返回已执行步骤、差异和修复提示。
- 完成校验识别批量查询以及组合验证中的成功步骤，减少因遗漏证据导致的重复调用；仍要求必要的真实修改与验证。

## 查看文件改动

对话中会显示「文件改动」区域，列出本轮成功新增、修改、删除的文件。展开每次操作可查看红绿代码差异、旧行号与新行号，以及增加/删除行数。运行时与历史对话共用同一份工具结果记录，也可在工具调用详情查看。

差异对应每次工具操作前后的文本，不依赖 Git，也不混入之前已有的工作区改动。同一文件多次编辑会分别显示操作记录。大文件或敏感文件只显示说明；过长差异会截断并标注。升级之前的历史记录未保存差异，无法补出当时的修改内容。
