# QQ 官方文档更新监控

监控 `https://bot.q.qq.com/wiki/` 下 sitemap 收录的全部官方文档，检测新增、修改和删除，并给主人和订阅群主动推送。默认每 **5 分钟**开始一轮全量正文核对，加载后立即检查一次。

## 行为

- 首次抓取建立基线，不推送历史页面；首轮失败的页面恢复后只补齐基线。后续真正新增但暂时抓取失败的页面，恢复后仍会推送新增通知。
- 每轮抓取全部页面并核对标题、正文、链接和图片地址，**不依赖 sitemap 的 `lastmod` 是否变化**。导航、脚本、构建资源和页尾更新时间不参与正文比较。
- 支持 sitemap 索引和无 XML 命名空间的目录。暂时从 sitemap 消失但仍能访问的旧页继续监控；连续两轮不在目录且返回 HTTP 404/410 才确认删除。抓取失败、验证页、软 404 或目录异常不会覆盖旧正文。
- 新快照与待推送通知原子写入同一份 `data/state.json`，落盘后再发送。通知失败不影响下一轮正文检查；即使本轮目录抓取失败，也会继续重试已有通知。
- 每个已启动机器人的全部 `owner_ids` 接收私聊通知；群订阅按设置命令收到的机器人 `appid` 保存，同一群在不同机器人下互不混用。订阅机器人的临时离线会保留待发通知。
- 文字通知只发送变更统计、页面标题和原文链接，**不再直接发送正文差异或新增正文摘要**。差异单独渲染成图片，包含文档标题、链接、原/现行号、增删行数和红绿对比。新增/删除文档显示完整正文，修改文档显示全部变更及附近上下文。
- 图片接入框架 `renderer` 模块，默认优先使用共享 PIL 子进程池，失败后尝试共享 Playwright 浏览器；上传到 `image_hosting` 图床后发送带尺寸的图片消息，同一批图片在所有主人和订阅群之间复用。机器人关闭 Markdown 时，通过图床直链上传 QQ 原生图片再推送。
- 图片宽度为 1200px，长行自动换行，超长差异自动分图并保留续页标题、行号，不截断变更。文字超长时按 UTF-8 字节数分段，按目标、按分段记录成功进度；重启后只补发未确认的分段。一个目标失败不会阻止其他目标收到通知，同一目标的多批通知按发现顺序发送。
- 渲染器或图床暂时不可用时，页面链接仍会发送，原始差异保存在队列中，下一轮检查或 `重试文档推送` 时自动补图。多张图片中途上传失败，重试时复用已成功上传的直链。图片错误通过 `文档监控状态` 查看。
- 尚无通知目标时保留队列，出现主人或订阅群后补发。取消群订阅同时取消对应机器人、对应群的待发通知。
- 发送接口返回的错误码、原因与抓取错误记录到 `data/status.json`，可通过状态命令查看。损坏的快照或订阅文件会明确报错，不会静默清空重建。

运行后自动生成 `data/config.yaml`：

```yaml
enabled: true
interval_minutes: 5
request_timeout_seconds: 30
concurrency: 8
request_retries: 2
max_message_bytes: 3500
send_timeout_seconds: 30
send_interval_seconds: 1
render_backend: auto
image_max_height: 12000
diff_context_lines: 2
font_path: ''
```

`interval_minutes` 最低按 1 分钟执行，兼容只有 `interval_seconds` 的旧配置。检查间隔按每轮开始时间计算，超过间隔的检查会跳过错过的时间点，避免任务重叠。检查和手动补发共用锁。

`request_retries` 只重试超时、连接错误及 HTTP 408/425/429/5xx；默认额外重试两次。并发范围 1～32；单段通知字节上限范围 512～4000，默认 3500；连续推送间隔默认 1 秒。

## 渲染与图床模块

在框架模块管理中安装并启用 **renderer** 和 **image_hosting**。图床上传使用 `upload_any()`，遵循图床模块已启用服务的优先级，并传入当前批次可用机器人的 TokenManager 和 sender；插件不单独保存图床密钥或启动浏览器。

- `render_backend: auto`：先判断 `renderer.pil_available()`，通过 `modules.renderer.protocol.render_pil()` 提交本插件的模块级函数及普通数据。PIL 不可用或渲染失败时，再使用 `renderer.playwright.new_page()`。`pil` / `playwright` 则固定使用对应引擎。
- 子引擎开关、进程池大小、浏览器安装和任务超时由 `modules/renderer/data/` 内的配置管理。插件卸载只停止自己的监控，不关闭共享渲染器。
- PIL 需要可用中文字体。默认寻找 Windows 微软雅黑、Linux Noto CJK / 文泉驿和 macOS 苹方；也可在 `font_path` 填写字体文件的绝对路径。Playwright 默认使用系统中文字体；配置了 `font_path` 时会内嵌该字体，不请求外部字体资源。
- `image_max_height` 范围为 2000～20000px，默认 12000px；超出高度自动分图。`diff_context_lines` 范围为 0～10，默认保留修改处前后各 2 行，所有变更行均会显示。

## 升级

直接更新整个插件目录并重载插件，保留原来的 `data/`。

- 自动迁移 v1 `state.json`，保留旧正文基线与 `subscriptions.json`，不强制改变用户设置的 1 分钟间隔。
- 原来只覆盖 `develop/api-v2/`，升级后首次为新范围的历史页建立基线，不集中发送历史页面。原范围内尚未发现的正文修改仍会参与比较。没有旧快照的历史改动无法追溯。
- 新版通知队列统一保存在 `state.json`，不再使用旧版 `delivery.json`。旧版未保存完整待发消息，升级时重新比较发现的变更可能再次发给已经收到过的目标。
- 兼容已有 v2 快照和待发队列；新发现的变更使用“链接 + 差异图片”。旧版队列补发前也会移除正文详情，保留页面标题、链接和原分段进度；原先未保存完整差异的批次无法补生成历史差异图。
- 主动消息是否可发送仍取决于对应机器人接口返回结果。发送 `测试文档推送` 可直接验证当前会话，失败会显示接口原因。

发送成功与进度落盘之间若进程突然退出，该分段可能重发；机器人接口不提供本插件可用的幂等确认机制，无法保证严格的恰好一次投递。

主人命令：

- `文档监控状态`
- `开放订阅群状态`（状态命令别名）
- `立即检查文档`
- `设置开放订阅群`（仅群内使用，绑定当前机器人 appid）
- `取消开放订阅群`（仅群内使用）
- `重试文档推送`（跳过抓取，立即补发队列）
- `测试文档推送`（向当前群或私聊发送主动测试消息，返回接口失败原因）

## 验证

在插件库根目录运行（测试依赖 `pytest`、`pytest-asyncio`、`httpx`；PIL 图片验证需 `Pillow` 和中文字体）：

```sh
python -m pytest QQ官方文档监控/tests -q -p no:cacheprovider
```

测试使用模拟 HTTP、图床与消息接口，不向实际主人或群发送消息。覆盖仅链接通知、差异行号与统计、多个修改片段、长行换行和分图、PIL PNG、HTML 转义、渲染模块公开协议和后端回退、上传失败后重启补图、目标失败隔离、取消订阅与顺序补发、图床直链复用以及损坏差异数据校验。
