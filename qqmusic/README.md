# 音乐点歌

作者：ElainaBot、24801816。

将整个 `qqmusic/` 目录放入 ElainaBot v2 的 `plugins/` 下并热重载。依赖框架已有的 `aiohttp`，语音转 SILK 由框架负责。默认 MP3 128kbps（`default_quality: 8`），已有配置值优先。

## 指令

| 指令 | 作用 |
| --- | --- |
| `点歌歌曲名` / `点歌 歌曲名` | 搜索 QQ 音乐 |
| `听1`、`听2` | 播放本用户上次搜索结果 |
| `音乐扫码登录` | 所有用户均可私聊扫码，自动轮询并通知结果 |
| `音乐登录状态` | 所有用户均可查询自己的登录、扫码进度、分池和续期状态 |
| `音乐在线账号数量` | 查看当前机器人的非绿钻、绿钻及以上账号数量 |

保持参考插件的搜索标题、用户 @、可点击歌曲名、“再点一首”按钮及点歌/听歌提示。播放成功只发送语音。搜索缓存按机器人、会话和用户隔离，有效期 10 分钟，最多 100 组。

所有文字回复（包括搜索、登录状态、登录结果与错误提示）显式使用 Markdown 消息，不依赖全局的 `message.use_markdown` 设置。登录二维码通过框架 `image_hosting` 图床模块的 `upload_any()` 自动上传，再以内嵌图片插入同一条 Markdown 消息；提示固定为“请使用QQ扫码登录”。图床沿用模块配置的启用状态和优先级，每次扫码使用唯一文件名。图床未启用或上传失败会提示原因并取消本次扫码轮询。

点歌按机器人隔离账号池，每次搜索从上次使用账号的下一个账号开始循环，普通、绿钻及待核验登录态均参与，搜索携带所选账号的登录凭据。遇到业务码 `2001`、`429`、`104604` 或 HTTP 429 自动切换下一个不同账号，最多切换 2 次（最多尝试 3 个账号）。同次搜索不会重试已经超频的账号，也不会因超频删除登录态。没有账号时仅尝试一次游客搜索。每个账号的相同成功搜索缓存 30 秒。

搜索最终失败时发送 Markdown 提示“当前账号获取列表超出频率限制，请稍后重试”，附绿钻账号登录说明，以及“音乐扫码登录”“音乐登录状态”两个按钮；具体异常继续记录在日志中。

## 个人登录与共享账号池

每个用户独立扫码，不会覆盖其他用户的二维码。状态查询只显示自己的账号，账号标识脱敏，不发送 Cookie。登录账号用于本机器人的共享点歌。不同机器人的账号池相互隔离；同一机器人下重复登录同一个 QQ 音乐账号会更新该记录，不会重复加入轮换。

账号登录后调用 `GetLoginUserInfo` 核验，再调用 `VipLogin.VipLoginInter / vip_login_base` 查询当前会员权益：

- `normal`：非绿钻账号。
- `vip`：绿钻、豪华绿钻、超级会员等绿钻及以上权益账号。
- `pending`：刚登录或接口异常导致暂时无法确认会员的账号，等待核验，不冒充普通账号。

播放按歌曲的 `pay.pay_play` 权限标志选择账号：普通歌曲先轮询选取一个普通账号，获取失败后直接使用绿钻池兜底；需要绿钻的歌曲只使用绿钻池，在该池内轮换。仅选择高音质不会让普通歌曲跳过普通账号。普通歌曲在账号池均不可用时仍可尝试游客播放，会员歌曲不会回退到普通账号或游客。未登录用户也可以点歌搜索。歌曲是否可播放仍受平台账号权益、版权和地区限制，空播放地址不会作为账号失效的依据。

后台默认每 300 秒复查全部账号，用户查询状态时立即复查自己的账号；播放前也会检查最近核验时间。会员到期后自动移入普通池，开通会员后自动移入绿钻池。以当前权益标志判断，历史会员等级不能证明会员仍有效。

`音乐在线账号数量` 根据当前账号池统计，不额外请求上游接口；所有用户均可在群聊或私聊查询。只展示当前机器人的数量，不展示账号标识或凭据。待核验登录态存在时单独列出并计入合计，确认失效并移除的账号自动扣除。

搜索或登录核验接口明确返回凭据失效业务码（1000、104400、104401）时，立即清除该账号登录态、用户归属和客户端缓存，并从账号池及 `data/accounts.json` 删除；搜索自动继续尝试下一个账号，仍遵守最多切换 2 次的上限。播放接口报告失效时通过登录接口确认后清理。到期前自动续期继续执行；网络异常、超频、风控、响应格式异常和歌曲版权限制不会导致账号被误删，正在进行的新扫码也会保留。

## 持久化与续期

所有凭据保存在 `data/accounts.json`：`pools.vip`、`pools.normal`、`pools.pending` 分开存储账号，`owners` 存储用户归属。使用临时文件替换写入，分类移动和归属变更一起保存。确定失效后从文件中删除，重启不会重新加载已删除记录。

自动续期默认开启，OAuth 令牌和音乐密钥以较早到期时间为准。可通过 `data/config.yaml` 调整 `auto_refresh`、`account_check_interval`、`refresh_before` 等配置。网络错误不保证可以立即续期，长期失效仍需重新扫码。

旧版 `data/credential.json` 会迁入待核验池，成功写入后删除旧文件；首次使用时绑定到对应机器人。旧版没有用户归属信息，因此原用户需再扫码一次才能通过个人状态查询看到该账号。升级部署时请保留原有 `data/`。

## 目录

```text
qqmusic/
  main.py                 # 元信息及显式加载入口
  app/
    runtime.py            # 运行实例、加载和卸载
    accounts.py           # 个人会话、分池、轮询、续期、清理
    client.py             # 腾讯接口、OAuth 扫码、歌曲和音质解析
    music.py              # 点歌与听歌指令
    login.py              # 扫码和个人登录状态指令
    qr_image.py           # 图床上传与 Markdown 二维码
    common.py             # 回复样式、搜索缓存
  tests/                  # 离线账号池及框架集成回归
```

内部保留歌词、歌曲详情、数字 ID 和音质解析能力，对外只注册上述五条指令。更新或卸载插件时会取消后台任务并关闭 HTTP 会话。

接口参数参照 [QQMusicApi 的用户模块](https://github.com/L-1124/QQMusicApi/blob/main/qqmusic_api/modules/user.py)和[登录模块](https://github.com/L-1124/QQMusicApi/blob/main/qqmusic_api/modules/login.py)，请求直接发送到腾讯接口。

`data/` 已排除版本控制，发布插件时不要打包其中的凭据。
