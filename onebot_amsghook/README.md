# 官机代发拦截插件

从 napcat-plugin-amsghook 完整迁移到 ElainaBot-Onebot1 的大型插件。插件拦截框架插件发起的 OneBot 消息发送，并可按来源插件改由 QQ 官方机器人发送。

框架内插件通过消息处理器、加载/卸载钩子、由这些入口创建的后台任务或插件 Web 路由发送消息时，均按插件文件夹名识别。管理页“来源插件规则”中选择对应目录名即可单独拦截；无法识别来源的调用才归入“OneBot 外部调用”。

## 依赖与安装

- 需要支持 api_interceptor 和 handler_filter 的 ElainaBot-Onebot1 版本。
- 自动群映射需要一个能向目标群发送消息的内置 QQ 或外接 OneBot 账号。
- 将整个 onebot_amsghook 目录安装到框架 plugins 目录，在后台侧边栏打开“官机代发”配置。

框架只提供通用的出站 API 中间件、处理器过滤器和内置 QQ 协议能力。本插件的配置、官机网关、拦截规则和映射均保留在插件目录内。

## 配置

在管理页填写 QQ 开放平台机器人的 AppID、Secret 和官机 QQ。管理页会自动读取全部可发现插件，包括未加载和已禁用插件，并与已有规则合并；无法识别来源的直接 OneBot 调用使用“OneBot 外部调用”。

- 官机代发：该来源的群消息改由官方机器人发送。
- 全局官机代发：所有支持的群消息都尝试由官方机器人发送。
- 仅主人、屏蔽群和屏蔽用户：可全局设置，也可对每个目标插件单独设置。

官机代发不需要额外开启规则级 HOOK；开启“官机代发”或“全局官机代发”即可。

官机必须已加入目标 QQ 群。群第一次触发代发时，插件会让 OneBot 账号 @ 官机；官机收到验证码后发送回调按钮，框架从消息 PB 提取按钮参数并点击换取 event_id。失败或超时会回退原始 OneBot 发送。
代发前会通过当前 OneBot 链路的群成员列表确认官机是否在群内；使用内置 QQ 时，查询和回退发送都走该内置 QQ。官机从未加入目标群、成员列表读取失败或官方发送失败时，消息均由原始 OneBot 账号发送。已建立的旧群映射不会跳过这项检查。
已完成映射的群默认使用按钮回调取得的 `event_id` 发送；`event_id` 缓存 4 分 30 秒，单个 event_id 最多使用 5 次，过期后插件会通过已保存的按钮映射自动点击刷新。按钮回调不可用或发送失败时，才回退到 v2 新接口主动发送。

官方 HTTP 与网关统一使用 `https://api.bot.qq.com` 新接口。图片和视频优先由 QQ API 直接读取 URL，失败后再通过复用连接下载上传；超过 5 MB 的本地媒体使用官方分片上传。图片仍可强制下载后重新上传，避免开放平台无法访问源地址。语音会使用插件 bin 目录中的 silk_codec 转码；系统需要可执行的 ffmpeg，或 Python 环境已安装 imageio-ffmpeg。转码条件不满足时会自动回退原始 OneBot 发送。

官机收到的群聊和私聊会重新注入框架插件事件链；已映射群会还原为真实 QQ 群号。主人可在群内发送 dm 内容直接走官机代发，发送“官机状态”查看连接状态，官机命令主人可与全局主人分开设置。管理页还支持网关启停、测试发送、规则批量切换和映射按钮发包。运行配置和群映射分别写入 data/config.json、data/mappings.json。
